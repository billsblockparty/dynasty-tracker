## Build and deploy

- Static GitHub Pages site. `.github/workflows/site.yml` runs on push to `pipeline/**`, weekly (Tue 10:17 and 15:17 UTC) and every 10 min in game windows (`live`).
- Modes (`pipeline/run.py <mode>`): `weekly` (pull completed week + full rebuild; push events use this), `live` (scores now), `build` (no network), `history`.
- Live runs do not commit data; weekly runs commit `pipeline/*.json` ("Save season data"). Workflow rebases with `-X theirs` on data conflicts.
- **BBP local build:** `cd pipeline && python3 run.py build` → `site/index.html`.
- **YILM local build:** `cd pipeline && python3 season_replay.py 2026 --build-only` → `.season/2026/site/index.html`. YILM builds by replaying its saved Sleeper data (`history/raw/<year>/*.json.gz`, refreshed in CI by `pull_season.mjs`) in a workspace copy `.season/<year>/pipeline`. Past seasons set `DT_PAST=1`.
- The sandbox has no network to Sleeper/MFL; data for local builds comes from the committed JSON (pull from origin first).
- YILM: every build pulls a fresh Sleeper capture in CI (`pull_season.mjs`); the Tuesday weekly run, pushes and manual runs then commit it (`pipeline/history/raw/<year>/`, "Save season capture [skip ci]"), so the repo holds the latest completed week. The 10-minute game-window runs do not commit. Before 2026-11-03 nothing committed it and the repo copy was stuck at Oct 31.

## Page architecture

- **`pipeline/readability.css` is appended last**: all recent overrides live at its end. Do not put `!important` on font sizes that JS fits (it blocks the fitter).
- `build_site.py` hides `body>*` until the page is fitted: the closing script reveals it only after the web fonts (Barlow Condensed 600/700, IBM Plex Sans 400/600) have loaded, `fonts.ready` has fired (the fitters hook it earlier, so they run first) and two frames have passed; 2.5s fallback, `<noscript>` reveal. Before this a refresh showed the pre-font fit and then visibly re-sized (streak tile, Could have). Page background from the last `--pg` in readability.css. It also builds the season/year buttons (`yrs`).
- Tabs: Standings, Leaderboards, Stats, Rosters, Matchups, Compare, Playoffs, Players, The Wire, Drafts, Paper Trail, Team Hub.
- **Navigation groups** (Nicklaus, 2026-11-03): `_navgroups()` at the end of `rebuild.py` turns the tab buttons into a sticky band `.tnav`: row 1 `nav.tabs` (existing nav button, 3 equal groups in this order since 2026-11-05: GAME DAY = Standings/Matchups/Playoffs, FRONT OFFICE = Rosters/Players/The Wire/Drafts/Paper Trail, THE LAB = Stats/Leaderboards/Compare/Team Hub; radios `grp-gd/fo/lab` sit just before `.tnav`); row 2 `.lbc.tsub` showing only the active group's tabs, styled as the H2H/Median toggle across the content width (2026-11-05; CSS block at the end of readability.css mirrors `.pane-st .tg`; BBP also lists `.tnav .lbc.tsub` in its `.pseg,.tg` --deck rule). JS at the end of new_tail.js: the group follows the selected tab (labels, FAAB tile, code, `#hash`), a group opens its first tab (Game Day opens Playoffs when `data-po=1`: Week 14 done and not a past season), `#standings`/`#the-wire`/`#tab-wr`... deep links win on load and on hashchange, tablist ARIA + roving tabindex + arrow/Home/End keys, `subFit()` picks the width rule (equal segments, or `.tsub.tfl` = each segment follows its label, measured with a Range on the label text), then, only if the row still overflows, eases segment padding (`--tsp`) to 6px, the gap (`--tsg`) to 5px and padding to 4px. The tab and group are NOT remembered across loads (build_site.py restore skips `name=tab`/`tgrp`); `history.scrollRestoration='manual'`. Each tab has a `*_build.py` writing `*_section.html` and `*_css.css` (see the header comment of each file).
- **On-demand tabs** (2026-11-04, Nicklaus; budget in `DESIGN.md` §7). `build_site.py` (current season only; past seasons, `DT_NOLAZY=1` and the download file stay one page) calls `lazy.chunk()`: every pane except Standings (and Playoffs when `data-po=1`) is cut out of index.html into `site/p/<pane>.<sha256 10>.html`; Matchups is cut again into a shell (`mu.*`) and one file per week (`mu-w<N>.*`, the shell keeps each empty `div.mwx-N`). Playoffs is cut one level deeper (`SUBS` in lazy.py): every bracket game panel `.bkp-*` and team panel `.psp-*` except the default-checked one becomes `po-bkp-*` / `po-psp-*` (`data-lzs` file, `data-lzr` radio), built when its radio is checked; with Playoffs as the opening tab (Weeks 15-17) the page is ~11k elements instead of 28k. `<style>` blocks found inside a cut pane are global (readability.css sits inside the Stats pane) and are moved, in order, to just after the last pane. Manifest `window.LZ` (`p`, `w`, `h` heavy panes, `k` storage key, `po`, `cw`). `lazy.js` (inlined): builds a pane on first open (innerHTML, then re-creates its `<script>`s in order, DOMContentLoaded/load handlers run straight after; avatar fill and Team Hub rank tiles redone), Matchups/Compare/Rosters dropped 1.5s after leaving and rebuilt with radios + inner scroll, other panes moved to a DocumentFragment while hidden (document queries only see the shown tab); the tab shown on load (default or #hash) is built before the reveal (`window.__pr`); loading frame `.lzf` after 300ms, "Couldn't load. Tap to retry" (a 404, i.e. a page older than the deploy, reloads once); prefetch on hover/touch/focus of a tab or group button; no copy of a built pane's HTML is kept (2026-11-05; Matchups/Compare/Rosters are fetched again on return, from the HTTP cache; the copies were ~5 MB of strings); radio state (`dt-radios`, was the inline restore script) kept for panes not on the page. A new tab is held open (`min-height`) from the radio's click event, before anything reads layout: a radio is already checked when its click runs, so a layout read there clamps the scroll (2026-11-04 bug in the first build). One resize dispatcher in `<head>` (`_RZ`): every `addEventListener('resize')` is collected and run once per frame, only when the width or pixel ratio changed; `window.__fitAll()` runs them on demand (lazy.js after each build). CI keeps the last 6 changed builds' chunks (`DT_CHUNKS`, actions/cache `.chunks`) so a page left open across a deploy can still open its tabs.
- Data pulls: `sleeper.mjs` (pure pull functions), `pull.mjs` CLI (`weekly`, `live`, `wire`, `top`, `detail`, `faab`, `state`), `drafts.mjs`, `history.mjs`, `fp_pull.py`.

### Fitting functions in new_tail.js (each owns one thing)

- **Memory rules for fitters** (2026-11-04, Safari/WebKit memory): (1) `FL()` (top of new_tail.js) is true while the web fonts load; each fitter's immediate first call is `if(!FL())X();` and its `fonts.ready.then(X)` call does the real pass (the page is hidden until then). (2) Never interleave layout reads and DOM/style writes per element: read everything, then write (`fit` and `inkBatch`). (3) Never set a custom property or class on `.board` in a loop: it restyles ~3,500 elements per step; set it on the elements that use it (`sbSet`: `--sbs` on `.r .sb, .r .st`, `--stw2` and `.sbm` on `.r>.sb`; `--s2s` on `.r>.st.s2`). (4) Reuse canvases (`FMC`, `INK`, `_cv`), never one per call. Each repeated fitting pass leaves JavaScript garbage that WebKit holds (all fitters off = −32 MB of JS heap). A `loadingdone` gate was tried and gave nothing measurable; not kept.
- `inkTile(t,H)` = `inkPlan` (reads only) + `inkSet` (writes) + `inkErr`/`inkFix` (one height read, one write). `inkBatch([[t,H],...])` does many tiles with one layout for all heights; `window.inkBatch` for other fitters.

- `tabFit`: tab labels. `ddFit`: dropdown labels.
- `tnFit`: standings names. First sets every row's name padding-right to clear the widest record tile (W3 4-3) + 6px, and gives all FAAB tiles one width. Then per name: one line if ≥85% of full size (22px, 19px ≤380), else two lines at the largest fitting size, three only when two would be <15px and three fit within 52px; never a cut word.
- `mvAl`: position-change arrow (inside the name text, after the last word, `.68em`) set on the name's cap centre via vertical-align; name block nudged so the name's cap top is level with the logo/face top.
- `ravFit`: legacy logo sizing (early-returns on BBP since the Hi/Lo line is gone).
- `sbFit`: stat lines PF/PA/Tot Eff share scale `--sbs` and text column `--stw2`; `.sbm` measures all rows so dots don't move between modes. Desktop (>=1100px): only PF/PA set the scale (Tot Eff is in the right column). If the 0.68 floor still cannot fit a line, the scale resets to 1 (it used to stick at the floor, so a 1px width change flipped all stat text between full size and 68% and moved the dots; reported on Nicklaus's Mac, not reproducible in Chromium).
- `s2Fit`: Opp/All-play/Luck line scale `--s2s` down to 0.81, else `.wrp` (Luck on its own line, all rows together).
- `fit` (= `window.tileFit`) + `inkTile`: rank tiles. Tile height = the figure's digit cap height to 0.25px (frames are inset shadows, inside that height; outer height trimmed to it exactly after sizing), digit-ink-to-frame gap 1.75-3.5px so the digits fill the tile, centred on the figure's cap height using its real baseline (a zero-size marker on it, read after sizing), on every line. Old transforms are cleared before the on-line check. Font metrics cache (`FM`) is cleared each run. Transform reset before measuring (re-runs never stack). Luck tile references the luck value, not the grey xW text (`.lku` skipped).
- `rrFit`: standings right column (streak tile size, Could have alignment), then re-runs `tnFit`. `rslFit`: Rosters season-totals line (own line when it would reach the points).
- `nrdFit`: desktop only, stacks the Nerd blocks in the right-hand column of each standings row.
- `rniSnap`: snaps numeral art to whole pixels. `finFit`: sim Finish tile height = projection figures.

## Gotchas learned the hard way

- `!important` font-size in CSS silently defeats JS fitting.
- Measure chips only after resetting transform; skip nothing in `fit` now (stat lines included).
- Measuring only visible rows changes widths between modes: measure all (`.sbm`).
- Canvas font metrics read before web fonts load are wrong: never cache across runs.
- Digit ink can rise above the H cap: size tiles on digit ink.
- Baselines estimated from canvas font metrics are off by up to ~0.9px at zoomed widths (1440 has `zoom` 1.1; layout rounds ascent/descent differently): measure with a zero-size inline-block on the baseline. `tilechk.py` now measures this way (it used to allow 0.6px, which hid it).
- A tile's stale `translateY` once made `fit` think it was off its line, so it was skipped forever (360: PF/PA tiles missing, 3.75px digits). Fixed by clearing transforms before the check.
- `new_tail.js` ends with `</script>`: append new JS before it.
- Zero-size baseline markers (`.ptbl`, tilechk's marker) only sit on the baseline in an inline formatting context; inside a flex/grid container they become items at the top. Verify alignment with a method independent of the fitter's own markers (2026-11-06: the Paper Trail NFL slot shipped 10px low and the marker-based check passed it).
- `const _cv` canvas already exists in new_tail.js: reuse, don't redeclare.
- YILM `live.js` is copied from BBP; `build_site.py` substitutes the YILM league id and season (was polling BBP's league before 2026-11-02).
- `live.js` holds no element references between polls (`rel()`, 2026-11-05): its `cells` NodeList kept the last Matchups week (23-27k nodes) alive after the tab was dropped.
- **Playoffs matchup builder** (`po_build.py`, while `WSP`): one gzip block per first team (`script#ppz-<a>`), unpacked when that team is picked; only the last block is kept, and a block that arrives after the selection changed draws nothing (2026-11-05: unpacking the whole set kept every pairing x week panel in memory once Playoffs was opened, 36 MB BBP / 54 MB YILM of 2-byte strings). `build_static.py` cuts from `.ppx` to the end of the builder script for the download file.
- `live.js` (2026-11-04): polls only while the current week's lineups are on the page (Matchups open on that week); on `panebuilt` it puts the last scores back at once and polls again if they are over 55s old. Tested with a replay (`debug/probe` feed shape, Playwright clock), base vs lazy identical. It never touched anything outside Matchups (same selectors before the chunk change); Standings/sim/headers update via the rebuild and the `#upd` refresh pill (build_site.py, inline in index.html, every tab).
- Local QA of any tab other than Standings needs http, not file:// (chunks are fetched): `python3 -m http.server` in `site/` (YILM `.season/2026/site/`). `tilechk.py` (Standings) still works on file://.
- Sleeper draft slot owners: derive from `draft_order` when `slot_to_roster_id` is empty; keep only the latest completed draft per season.
- Playoff orange bars (Week 15): total of both wild-card games, averaged across seasons.

### Local sandbox setup (no network to Sleeper)

- **BBP Team Hub** (`teamhub/build.py`) calls Sleeper even in `build` mode; offline it fails with a 403 tunnel error. It is non-fatal by design: the main site still builds. Ignore it locally.
- **YILM first build:** `season_replay.py 2026 --build-only` fails (`.season/2026/pipeline/... not found`) until one full offline replay has run: `python3 season_replay.py 2026` (uses the committed capture, no network). After that, `--build-only` works.
- **YILM Playwright:** do not `npm i` in `pipeline/`. `package.json` pins Playwright 1.47.2, which wants browser build chromium-1134; the sandbox has chromium-1243 only, so `gen.js` fails with "Executable doesn't exist". Without a local `node_modules`, `gen.js` resolves the global Playwright (as BBP does). If one was installed, `rm -rf pipeline/node_modules .season/2026/pipeline/node_modules` and rebuild.

## QA tools (tools/)

- `realfonts.py`: real fonts in Playwright (required).
- `device.py` (2026-11-05): iPhone Safari emulation for `tilechk.py`/`shots.py` width tokens `360P 402P 440P 874L 956L` (isMobile, hasTouch, Safari UA, DPR 3; Chromium applies the pages' `initial-scale=0.85` meta like Safari, so 402P lays out at 472 CSS px, 956L at 1124 = desktop layout). Plain numbers behave as before. `DT_ZOOM` / `956L@0.85` adds a Safari page zoom on top (default 1). Report device measurements in points (CSS px x 0.85). Run `tilechk.py 360P 402P 440P 874L 956L 402 440 360 1440` = 0 violations. WebKitGTK (tools/mem) ignores the viewport meta: its figures are at plain CSS widths.
- `shots.py`: full-page captures of every tab + Standings with Nerd on, per width (`shots.py <url> <dir> 402 1440`), and `--cmp <a> <b>` (identical / pixel count and max channel difference). Two runs of the same YILM build differ by up to 2/255 in the sticky nav band on Matchups and Stats at 402 (raster noise); compare against a second "before" run when that shows up.
- `mem/leaks.py`: opens every tab, returns to Standings, forces GC, then reports DOM counters (live nodes incl. off-page, listeners), JS heap by type at load and at the end, and detached DOM trees with their retaining paths. The detached-node count swings between runs (parked panes' nodes are flagged inconsistently); compare the counters. `mem/chmem.py` with `GC=1` forces a collection before each reading (without it, figures move 10-18 MB with GC timing).
- `mem/`: WebKit (WebKitGTK via apt; Playwright's WebKit download is blocked by the sandbox allowlist) and Chromium memory per tab; see `tools/mem/README.md`.
- `tilechk.py`: every tile beside a figure spans exactly its cap height (real baseline via a zero-size marker, real CSS zoom, tolerance 0.05px, `TOL=` to loosen); stat-line tiles off their line count as violations; Dumb and Nerd; both trackers, any widths; exit code 1 on any violation. Against the pre-2026-11-02 fitter it fails 80-98% of tiles; the old version passed them all.
- `fab.py`: per-row name size/height/clip report + crops. `shot.py`: name-block-only screenshots at 402/440.
