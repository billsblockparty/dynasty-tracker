## Standing rules (from Nicklaus; non-negotiable)

## Build and deploy

- Static GitHub Pages site. `.github/workflows/site.yml` runs on push to `pipeline/**`, weekly (Tue 10:17 and 15:17 UTC; YILM Tue 10:17 only), **daily at 8:30 AM New York time** (crons `30 12 * * *` + `30 13 * * *`; the `gate` job keeps the one matching New York's current offset, -0400 EDT / -0500 EST, so exactly one runs per day even if GitHub starts it late) and every 10 min in game windows (`live`; a game-window run in New York's 8 AM hour is skipped, no game starts before 9:30 AM ET). The `gate` job picks the mode; skipped runs never enter the build job's concurrency group `site` (job-level since 2026-11-12), so they cannot cancel a queued run.

With no newly completed week (`run.py`, `D<=have`), `pull.mjs midweek G` (same pull as `weekly G`, but writes only `pull8.json`, `pull8a.json` and `pull_m7.json` RO/TP; `pull_pts.json` and week G's matchups are kept) + `midweek.py G` rewrite `rosters.json`, `ro_ranks.json`, `ro_pg.json`, `wk<G+1>.json` (current rosters and set lineups; the file's live scores, done/live/left and the team of a player who has already played are kept), `kick.json[G+1]`, FUT week G+1 projected totals and win % in data_block.js, new players' ages in cmp_extra.json; it prints a roster check (Sleeper vs rosters.json and wk<G+1>, warnings only). ### Fitting functions in new_tail.js (each owns one thing)

- **Memory rules for fitters** (2026-11-04, Safari/WebKit memory): (1) `FL()` (top of new_tail.js) is true while the web fonts load; each fitter's immediate first call is `if(!FL())X();` and its `fonts.ready.then(X)` call does the real pass (the page is hidden until then). (2) Never interleave layout reads and DOM/style writes per element: read everything, then write (`fit` and `inkBatch`). (3) Never set a custom property or class on `.board` in a loop: it restyles ~3,500 elements per step; set it on the elements that use it (`sbSet`: `--sbs` on `.r .sb, .r .st`, `--stw2` and `.sbm` on `.r>.sb`; `--s2s` on `.r>.st.s2`). (4) Reuse canvases (`FMC`, `INK`, `_cv`), never one per call. Each repeated fitting pass leaves JavaScript garbage that WebKit holds (all fitters off = −32 MB of JS heap). A `loadingdone` gate was tried and gave nothing measurable; not kept.
- `inkTile(t,H)` = `inkPlan` (reads only) + `inkSet` (writes) + `inkErr`/`inkFix` (one height read, one write). `inkBatch([[t,H],...])` does many tiles with one layout for all heights; `window.inkBatch` for other fitters.

- `tabFit`: tab labels. `ddFit`: dropdown labels.
- `tnFit`: standings names. First sets every row's name padding-right to clear the widest record tile (W3 4-3) + 6px, and gives all FAAB tiles one width. Then per name: one line if ≥85% of full size (22px, 19px ≤380), else two lines at the largest fitting size, three only when two would be <15px and three fit within 52px; never a cut word.
- `mvAl`: position-change arrow (inside the name text, after the last word, `.68em`) set on the name's cap centre via vertical-align; name block nudged so the name's cap top is level with the logo/face top.
- `ravFit`: legacy logo sizing (early-returns on BBP since the Hi/Lo line is gone).
- `sbFit`: stat lines PF/PA/Tot Eff share scale `--sbs` and text column `--stw2`; `.sbm` measures all rows so dots don't move between modes. Desktop (>=1100px): only PF/PA set the scale (Tot Eff is in the right column). If the 0.68 floor still cannot fit a line, the scale resets to 1 (it used to stick at the floor, so a 1px width change flipped all stat text between full size and 68% and moved the dots; reported on Nicklaus's Mac, not reproducible in Chromium).
- `s2Fit`: Opp/All-play/Luck line scale `--s2s` down to 0.81, else `.wrp` (Luck on its own line, all rows together). The H2H/Median buttons fire `click`, not `change`, and `draw()` rebuilds every row: `set()` runs `tileFit()`, `s2Fit()`, `sbFit()` after it (2026-11-14; chips first, or the unfitted chips make Luck wrap at 440P).
- `fit` (= `window.tileFit`) + `inkTile`: rank tiles. Tile height = the figure's digit cap height to 0.25px (frames are inset shadows, inside that height; outer height trimmed to it exactly after sizing), digit-ink-to-frame gap 1.75-3.5px so the digits fill the tile, centred on the figure's cap height using its real baseline (a zero-size marker on it, read after sizing), on every line. Old transforms are cleared before the on-line check. Font metrics cache (`FM`) is cleared each run. Transform reset before measuring (re-runs never stack). Luck tile references the luck value, not the grey xW text (`.lku` skipped). `ref()` returns null for chips in `.csr` (Compare › Schedule › Week by week, 2026-11-14): its parent-sibling branch took the "Wk 10" label as the right-hand chip's figure; the branch stays (YILM Stats uses it).
- `rrFit`: standings right column (streak tile size, Could have alignment), then re-runs `tnFit`. `rslFit`: Rosters season-totals line (own line when it would reach the points).
- `nrdFit`: desktop only, stacks the Nerd blocks in the right-hand column of each standings row.
- `rniSnap`: snaps numeral art to whole pixels. `finFit`: sim Finish tile height = projection figures.

## Gotchas learned the hard way

- `!important` font-size in CSS silently defeats JS fitting.
- Measure chips only after resetting transform; skip nothing in `fit` now (stat lines included).
- Measuring only visible rows changes widths between modes: measure all (`.sbm`).
- Canvas font metrics read before web fonts load are wrong: never cache across runs.
- Digit ink can rise above the H cap: size tiles on digit ink.
- Baselines estimated from canvas font metrics are off by up to ~0.9px at zoomed widths (1440 has `zoom` 1.1; layout rounds ascent/descent differently): measure with a zero-size inline-block on the baseline. `tilechk.py` now measures this way (it used to allow 0.6px, which hid it).
- A tile's stale `translateY` once made `fit` think it was off its line, so it was skipped forever (360: PF/PA tiles missing, 3.75px digits). Fixed by clearing transforms before the check.
- `new_tail.js` ends with `</script>`: append new JS before it.
- Zero-size baseline markers (`.ptbl`, tilechk's marker) only sit on the baseline in an inline formatting context; inside a flex/grid container they become items at the top. Verify alignment with a method independent of the fitter's own markers (2026-11-06: the Paper Trail NFL slot shipped 10px low and the marker-based check passed it). Since 2026-11-14 `fit()` handles a text run that is itself a flex / grid item (`fx`, e.g. Matchups "Week rank", Stats › Consistency figures): the run and its marker go into a temporary `<fit-w style="all:unset">`, unwrapped after the read (a `span` wrapper picked up page CSS and put the marker 3px low).
- `const _cv` canvas already exists in new_tail.js: reuse, don't redeclare.
- Class `r` is both the Standings row and the Matchups / Playoffs road tile (`.gha.ht.r`): the row rule in new_head.html is `.r:where(:not(.gha))` (2026-11-14); a new box rule for standings rows must not use a bare `.r`. The road tile's padding-top is 1px (readability.css) to hold the glyph where the leaked border held it.
- Canvas `measureText` cannot measure tabular figures (no `font-variant-numeric`), and WebKit's canvas reports the advance box, not glyph ink (`actualBoundingBoxLeft/Right` = 0 / advance in WebKitGTK); browsers also snap text to a pixel grid (WebKit device px, headless Chromium whole CSS px / points). A centring check built on the fitter's canvas passes what the screen gets wrong (Paper Trail TIMES TRADED "1", 2026-11-07): measure tile centring from screenshots (pixel ink with coverage-weighted edges, both engines; WebKitGTK via tools/mem with `GDK_SCALE=3`).
- **Live scores never assert** (2026-11-08): a starter missing from his roster's rows in `wk<W>.json` (added after it was written, e.g. Malik Washington 11610 dropped by BBP roster 1 and added by roster 7, still on roster 1's bench) was dropped from the lineup, and `score.py`'s `assert sum(st)==tp` failed every BBP live run from 19:54Z (roster 7 3.10 short; scores frozen). Now `pull.mjs live` passes `known` per roster and `pullLive` returns any starter not on his own roster's rows as `extra`; `score.py` takes the row from `extra`, else from the roster that still lists him, else a minimal row (never drops a starter), removes him from every other roster's rows (a final pass: whoever starts for one roster is on no other), and on a sum mismatch prints a WARNING (roster, sum, Sleeper total, ids without row/points) and keeps Sleeper's team total. `full_update.py`'s starter-sum check is a warning too. Never add a fatal assert to the live path.
- **Mid-week NFL team changes** (2026-11-12): Josh Downs (IND -> KC) and Keenan Allen (IND -> SF), traded 10 Nov, stayed IND with the Colts' Week 10 opponent in every BBP file although Sleeper's players map said KC/SF. Cause: only the completed-week pull (`pullWeekly` -> `full_update.py`) writes `pull8.json`, `rosters.json` and `wk<W>.json` teams; mid-week weekly runs (`D<=have`) and live runs never re-read them, and `pullTop` preferred the last stat line's team. Fix: `pull.mjs teams W [full]` (`pullTeams`) + `teams.py` patch the current week only (wk<W> row team + opponent, pull8 META team + PJ opponent, rosters.json, pull_top.json); weekly runs read the players map (`full`), live runs only when week W's projections name a different team; a row whose player already has a week-W stat line keeps his team; never fatal; output `pull_teams.json`. `pullTop` now takes the players map's team. YILM had the inverse fault: its replay reads today's players map for every week, so traded players carried KC/SF into Weeks 1-9 (with the new team's opponents in hist.json); `pullWeekly` now takes week N's team from the stat line when week N is complete (else its projection, else his last team), and `pullLive` extra rows from the week's stat line.
- YILM `live.js` is copied from BBP; `build_site.py` substitutes the YILM league id and season (was polling BBP's league before 2026-11-02).

## QA tools (tools/)

- `realfonts.py`: real fonts in Playwright (required).
- `device.py` (2026-11-05): iPhone Safari emulation for `tilechk.py`/`shots.py` width tokens `360P 402P 440P 874L 956L` (isMobile, hasTouch, Safari UA, DPR 3; Chromium applies the pages' `initial-scale=0.85` meta like Safari, so 402P lays out at 472 CSS px, 956L at 1124 = desktop layout). Plain numbers behave as before. `DT_ZOOM` / `956L@0.85` adds a Safari page zoom on top (default 1). Report device measurements in points (CSS px x 0.85). Run `tilechk.py 360P 402P 440P 874L 956L 402 440 360 1440` = 0 violations. WebKitGTK (tools/mem) ignores the viewport meta: its figures are at plain CSS widths.
- `shots.py`: full-page captures of every tab + Standings with Nerd on, per width (`shots.py <url> <dir> 402 1440`), and `--cmp <a> <b>` (identical / pixel count and max channel difference). Two runs of the same YILM build differ by up to 2/255 in the sticky nav band on Matchups and Stats at 402 (raster noise); compare against a second "before" run when that shows up.
- `mem/leaks.py`: opens every tab, returns to Standings, forces GC, then reports DOM counters (live nodes incl. off-page, listeners), JS heap by type at load and at the end, and detached DOM trees with their retaining paths. The detached-node count swings between runs (parked panes' nodes are flagged inconsistently); compare the counters. `mem/chmem.py` with `GC=1` forces a collection before each reading (without it, figures move 10-18 MB with GC timing).
- `mem/`: WebKit (WebKitGTK via apt; Playwright's WebKit download is blocked by the sandbox allowlist) and Chromium memory per tab; see `tools/mem/README.md`.
- `tilechk.py`: every tile beside a figure spans exactly its cap height (real baseline via a zero-size marker, real CSS zoom, tolerance 0.05px, `TOL=` to loosen); stat-line tiles off their line count as violations; Dumb and Nerd; both trackers, any widths; exit code 1 on any violation. Against the pre-2026-11-02 fitter it fails 80-98% of tiles; the old version passed them all.
- `fab.py`: per-row name size/height/clip report + crops. `shot.py`: name-block-only screenshots at 402/440.
